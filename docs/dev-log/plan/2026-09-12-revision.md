# The revision: from manual back to textbook

Started 2026-09-12. Source of truth for what to change: `docs/dev-log/review/2026-09-12-pedagogy-audit.md`.
This file is the plan, kept short so it can be re-read every arc. The audit holds the evidence.

## Goal

Every class teaches a reader who is learning Julia and statistics at the same time, and none reads
as documentation of the engine. The measure is the audit's own: a reader finishing a class can say
what she can now do that she could not before, and could write the code.

## Constraints that do not bend

- Never invent output. Every number still comes from the run. Cutting code that produced a number
  means cutting the number, or computing it more cheaply, never typing it.
- What must survive is listed in audit section 2. A cut that damages any item there is a regression,
  whatever it saves.
- One engine taught. The comparison boxes stay rare and earned.
- Every revised chapter re-renders, passes its gate ledger, and goes through the three review lenses
  (stats-reviewer, coherence-checker, graphics-editor) before it is published.
- Do not publish a half-revised book. A reader must never meet a chapter pointing at an appendix that
  does not exist yet.

## The one authorial decision, and the working assumption

Appendix A: promote it to a class (designer) or keep it as the pacing template and move the
methodology into it (student; the audit leans this way). **Working assumption: keep it as the
template.** It changes Appendix A least and reverses cheaply now, expensively after wave 2.

## Word budget

The chapters both reviewers called teaching run 7,900 to 8,500 words including code. Every class
comes to at most 9,500. Starting points: Class 10 17,100 · Class 7 16,800 · Class 9 16,700 ·
Class 5 13,600 · Class 4 11,100 · Class 6 10,700 · Class 8 9,700.

## Waves

**Wave 1.** The engine appendix, `book/appendix-b-engine.qmd`, "Where the engine stops": every
limitation, quirk, refusal and issue number in one table (feature · status at the pinned version ·
workaround · issue), registered in `index.qmd`. In parallel, the five worst classes cut per audit
section 5: 4, 5, 7, 9, 10. Forensics out or reduced to the one number each produced; issue numbers
and version strings out of prose; "reported to the engine's authors" out; the `simulate` trap stated
once in the book; the teacher-wrong-on-the-page tic removed except where the correction is the lesson.

**Wave 2.** Classes 2, 3, 6, 8: lighter cuts per section 5. Then two cross-cutting passes that must
run after the cuts, because cutting code changes what needs teaching: the Julia thread (introduce
broadcasting, comprehensions, loops, functions, Dicts, NamedTuples, try/catch where each is first
used; rewrite every "Julia stuff" summary as language, not accessors), and the exercises (data for
every named organism, graded, somewhere to check yourself).

**Wave 3.** The cross-chapter pass: callbacks still land, forward pointers still point at something,
the arc reads as one climb. Then the standard publish.

## Ownership

One agent per chapter file. The appendix agent owns `book/appendix-b-engine.qmd` and the two lines
in `index.qmd` that list it. Nobody edits `tools/` in this arc. Cross-cutting passes run alone.
