# Reader pass — Chapters 7 and 9

## Who did this and how

Read as the book's intended reader: a biology graduate student with one statistics course and no
Julia. Read `docs/writing-conventions.md` first, especially "What a reader must never meet." Then
read both chapter sources (`book/wk7-random-slopes.qmd`, `book/wk9-glmms.qmd`) end to end, and read
the **rendered** pages served from the local preview
(`http://127.0.0.1:8934/book/wk7-random-slopes.html`, `.../wk9-glmms.html`), extracted to plain text
with `html.parser` so nothing in a code block, a warning, or a stack trace could hide from the
search. Everything quoted below is what the reader actually meets on the page, not just what is in
the `.qmd` source.

## Verdict

| Page | Verdict |
|---|---|
| Chapter 7 (`wk7-random-slopes`) | **Real pass** |
| Chapter 9 (`wk9-glmms`) | **Real pass** — worse than Chapter 7 |

Both chapters are statistically excellent and, sentence for sentence, mostly written in the cast's
voice correctly. But both fail the one rule this pass exists to check: machinery from the build
system reaches the reader, and in Chapter 9 especially it reaches the reader **repeatedly and
verbatim**, not as a stray phrase but as full engine stack traces with a real person's local
filesystem path in them. This is not a polish job. Every instance below needs a decision (cut,
rewrite, or — for the printed stack traces — a build-side fix that no amount of prose editing can
substitute for) before either chapter is reader-ready.

The single biggest fix available to both chapters at once: **the crash cells print Julia's full
stack trace**, including `~/.julia/packages/<Package>/<hash>/src/<file>.jl:<line>` for every frame,
down through `ForwardDiff`, `Optim`, `LineSearches` and `NLSolversBase` in Chapter 7 alone. This is
not prose that can be rewritten in the cast's voice — it is unfiltered program output, and it is the
single worst thing on either page. It needs a Quarto/engine-side fix (print only
`sprint(showerror, e)`'s first line, or catch and reformat before display) — see the note at the end
of each chapter's list.

   at zero, not the adaptive one — the engine says so itself, however close the two numbers land."
   Drop the file names and "read the source" entirely; the teaching point survives without them.

4. **Ch7, "The correlation you did not ask for," Itchy.** *"Where is it, then? In the engine's own
   arithmetic, and you can read it, because the source is open. `src/gaussian_ranef.jl` carries the
   Cholesky diagonals as logarithms and exponentiates them, `l11 = exp(a)`, `l22 = exp(b)` — check it
   against the printed block: `L11` was {inline number}, which is the logarithm of σ_0. So a
   standard deviation is never handed to `log` anywhere in that objective. The only logarithm in it
   is `logdetM += log(dM)`, where `dM = m11*m22 - m21^2` is a two-by-two determinant computed once
   per bird."* This is the exact phrase-shape the convention warns about: an engine source filename
   and a line of its literal code, in dialogue.
   **Rewrite:** "Where is it, then? In the engine's own arithmetic. It keeps every standard
   deviation positive by never handing it to `log` directly — check it against the printed block:
   `L11` was {inline number}, which is the *logarithm* of σ_0, not σ_0 itself. What does get logged
   is a small determinant, computed once per bird from the covariance matrix. With uncentred mass
   that determinant is the difference of two very large, nearly-equal numbers, and in floating-point
   arithmetic that difference can come out negative — and you cannot take the logarithm of a
   negative number."

## Chapter 7 — `wk7-random-slopes.qmd` / `wk7-random-slopes.html`

**Rank: real pass.**

### Machinery reaching the reader (full list, beyond the top ten above)

- **"Freeing the slope," code output.** Full stack trace, `~/.julia/packages/...` paths through
  `ForwardDiff`, `Optim`, `LineSearches`, `NLSolversBase` (item 1 above). *Needs a build-side fix,
  not a prose rewrite* — see note below.
- **"The correlation you did not ask for," Itchy** — the `gaussian_ranef.jl` / `l11 = exp(a)` /
  `log(dM)` passage (item 4 above).
- **"The correlation you did not ask for," Itchy** — `DRM.jl issue #762` in dialogue, repeated in
  Summary (item 9).
- **"What has to wait," Itchy** — `DRM.jl issue #753` in dialogue with a live GitHub link (item 8).
- **"The slope that was doing two jobs," Itchy + code** — "ledger," "said (blended)" / "is
  (separated)" (item 10).
- **Julia stuff, last bullet.** *"Reading a `DomainError` from a mixed fit. … the Cholesky diagonals
  are carried as logs and exponentiated (`gaussian_ranef.jl`)."* Same file name repeated a third
  time in the chapter, this time in the Julia-stuff summary itself.
  **Rewrite:** "Reading a `DomainError` from a mixed fit. It is a logarithm of a negative number
  inside the optimiser, and in this engine that logarithm is never of a standard deviation itself —
  standard deviations are kept positive by construction. Two very different things make the
  underlying determinant go negative: a far-away origin, with Σ perfectly healthy, and a genuinely
  collapsing Σ. Check which before you conclude anything…" (drop the filename in parentheses).

### Statistical terms and abbreviations

- **"What the model does to a bird's own slope," figure caption.** *"read 'raw mean' as the unshrunk
  estimate and 'BLUP' as the model's."* This is the first use of **BLUP** in this chapter, and it is
  glossed only inside a figure caption, only by reference back to Class 6, and never expanded (Best
  Linear Unbiased Predictor). A reader who has not just re-read Class 6's caption meets an
  unexplained abbreviation.
  **Rewrite (keep the caption's structure, expand on first use):** "…diamonds are what the model
  predicts for the same bird — its BLUP (best linear unbiased predictor), the model's own shrunk
  estimate, as introduced in Class 6."
- **"Freeing the slope," Itchy.** *"There is no `resd` line this time; there is a random-effect
  covariance block — the engine calls it `recov`… printed as a **Cholesky factor**, with three
  entries in it."* "Cholesky factor" is used repeatedly through the chapter (six times) but never
  given a one-line plain-language gloss (e.g., "a way of writing a covariance matrix as the product
  of a lower-triangular matrix with itself, chosen because it keeps the matrix valid during
  fitting"). A biology-trained reader with one stats course has very likely never met the term.
  **Rewrite (first use):** "…printed as a **Cholesky factor** — a triangular breakdown of the
  covariance matrix that the optimiser uses internally to guarantee the matrix stays valid while it
  searches — with three entries in it."
- **"Is the extra term worth it," Momo/Jaro dialogue.** The **Stram & Lee mixture** and **boundary**
  test are introduced and explained reasonably well in Jaro's speech (a strength of this chapter —
  keep as is). "Boundary" itself is defined cleanly on first substantive use: *"σ_1 cannot be
  negative, so testing it at zero is a test on the boundary of the parameter space."* No fix needed
  here — flagging only to note it was checked and passes.

### Sentences too long to parse

- **"The slope you have been sharing," Itchy** (one sentence spans the whole explanation of the
  bird-term trade-off): *"Two things happen at once when you add `(1 | g)`: you stop counting
  repeated measurements as fresh evidence, which pushes the standard error up, and you take an
  enormous amount of noise out of the residual, which pulls it down."* This one is fine (two clean
  clauses); flagging as a **borderline pass** example, not a fix.
- **"What the model does to a bird's own slope," Itchy** — the sentence beginning *"Because a
  predicted effect is shrunk and a variance component is not… The second is the smaller of the two
  **in expectation**, in every mixed model you will ever fit — and note that 'in expectation' is
  doing work, because the spread of a handful of predictions is itself a random quantity."* Three
  ideas stacked in one breath (why they differ, that it's an expectation claim, and a
  meta-comment about the phrase "in expectation" doing work). Light pass — split into two sentences:
  one giving the mechanism, a second flagging the "in expectation" caveat.

### Numbers without comparison

- No unanchored bare numbers were found — every inline number in this chapter is immediately
  compared against another number in the same sentence (a ratio, a "compared with," a before/after).
  This is a genuine strength of the chapter; **keep every inline number exactly as it is.**

### Dialogue reading as authors-talking-to-each-other

- **"Is the extra term worth it," Jaro.** *"Because `lrt_boundary` with *q* equal to two implements
  a different mixture, and its documentation says which…"* This is close to the line — "its
  documentation says" is citing a docstring rather than teaching a concept — but the sentence goes
  on to explain the actual statistical distinction (independent boundary parameters vs. a
  variance-and-correlation pair), so it lands as teaching, not as two engineers comparing notes on a
  package. **Light pass**, not blocking.

### Build-side fix needed (not a prose problem)

The two full stack traces in this chapter (item 1 above, and the second, caught-and-reported
version inside `boundary-study`'s `catch` block — which is fine, since it only prints
`nameof(typeof(e))`, e.g. `DomainError`) show the fix that already half-exists in the chapter: catch
the exception and print only its type or its first line, the way `boundary-study` already does for
the 400-replicate loop. The one **uncaught** crash cell (`#| label: fit-uncentred`, `#| error:
true`) should either be wrapped the same way, or — if the raw crash is pedagogically wanted, which is
plausible given the lesson — Quarto/Julia should be configured to print only
`sprint(showerror, e)`'s message line, dropping everything from `Stacktrace:` down.

## Cross-cutting notes

- **Both chapters over-cite GitHub issues.** The convention allows "at most one, in a Julia-stuff
  bullet, as 'a known limitation, reported.'" Chapter 7 has two live-linked issue numbers in
  dialogue (#762, #753) plus a third bare mention in a Julia-stuff bullet (#762 again). Chapter 9 has
  three (#761 twice, #73 once), none phrased as the convention specifies. Recommend a single pass
  across both chapters that keeps **at most one** issue mention per chapter, in a Julia-stuff bullet,
  worded "a known limitation, already reported" — no number, no link.
- **Every stack trace on both pages needs the same build-side fix.** This is the highest-leverage
  single change available: whatever mechanism `boundary-study`'s `try/catch` in Chapter 7 already
  uses to print only `nameof(typeof(e))` should be applied everywhere a crash is shown deliberately,
  and Quarto's default full-traceback rendering should be suppressed globally for `#| error: true`
  cells (print `sprint(showerror, e)`'s first line only). Doing this once, in the shared tooling,
  fixes items 1, 2, 5, 6, and the `comparison.jl`/`vcov_guard.jl` warning blocks in one move — it is
  not a per-chapter prose fix.
- Both chapters are otherwise strong: numbers are always compared, not asserted bare; most technical
  terms get a real plain-language gloss on first use (the latent-ICC and quadrature boxes in Chapter
  9 are genuinely good models for how to do this); and the dialogue reads as a class, not as authors
  narrating their own repo, apart from the handful of lines flagged above.
